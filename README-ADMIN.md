
# Админ-панель (дополнение)

Добавлены `admin.html`, `admin.css`, `admin.js`, `supabase-config.js` и `supabase-setup.sql`.
Адрес панели после публикации: `https://wepoftus-star.github.io/my-store/admin.html`

## Подключение админ-панели

Панель использует Supabase Auth, Postgres и Storage. Нужна первоначальная настройка один раз.

1. Создайте проект в https://supabase.com/.
2. В SQL Editor выполните весь файл `supabase-setup.sql`.
3. В Storage создайте bucket `product-photos` и включите Public bucket (публичное чтение фото, но загрузка требует входа). SQL-политики из файла ограничивают операции загрузки/изменения/удаления только авторизованными пользователями.
4. В Supabase → Authentication → Users добавьте пользователя администратора вручную. Используйте уникальный надёжный пароль. Публичной формы регистрации на сайте нет.
5. В Project Settings → API скопируйте Project URL и **anon/public key** в `supabase-config.js`. Никогда не используйте `service_role` key в файлах сайта.
6. Загрузите новые файлы в корень GitHub Pages репозитория.
7. Откройте `/admin.html`, войдите по созданному email и паролю. Можно создавать, редактировать, скрывать и удалять карточки, менять описание/цену и загружать фото.

## Важно: подключить публичный каталог к данным

Текущая главная `index.html` из первой версии содержит демонстрационные статические карточки. Админ-панель сохраняет изменения в Supabase, но для автоматического появления этих изменений на главной нужно заменить статический рендер каталога на чтение `products` из Supabase. Этот этап не следует пропускать: иначе админка и публичная витрина не будут синхронизированы. В этой сборке подготовлена безопасная панель и схема базы, но публичный каталог пока остаётся демонстрационным. Также после включения Supabase нужно проверить, что все записи читаются по RLS, а редактирование доступно только вашему аккаунту администратора.


## Синхронизация публичного каталога — уже включена в этой версии

`index.html` загружает Supabase JS и `supabase-config.js`. `script.js` читает опубликованные записи (`active = true`) из таблицы `products`. Сохранённые в админ-панели изменения (название, описание, цена, фото, категория, видимость) должны появляться на главной после перезагрузки страницы.

## Усиление защиты администратора

- В Supabase → Authentication → Settings отключите публичные sign-ups (Allow new users to sign up), если эта настройка доступна в вашем проекте.
- Создавайте администратора вручную через Dashboard → Authentication → Users.
- Не используйте слабый пароль и не передавайте его посетителям сайта.
- Политики SQL разрешают изменение таблицы только роли `authenticated`; поскольку публичная регистрация отключена и пользователь создаётся вручную, доступ к панели получают только ваши аккаунты. Если добавите других пользователей, все аутентифицированные пользователи получат доступ к редактированию — в таком случае надо добавить отдельную роль администратора и ограничить RLS по ней.
- Фото находятся в публичном bucket, поэтому любой может просматривать изображения по их URL. Загрузка и изменение объектов требуют авторизации.
